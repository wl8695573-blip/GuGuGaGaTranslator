# 公共术语库

本目录保存 LCTA 可下载的《边狱巴士》术语档案。`limbus-company.ggprofile.json` 是数据，`manifest.json` 记录版本和原始文件的 SHA256。程序随包附带这两个文件；检查更新时读取原仓库 `main` 分支中的同一路径。

## 用户如何更新

LCTA 1.5.0 起，在“支持 → 程序与公共词库更新”点击“检查更新”。发现新词库后可手动应用，也可勾选自动应用。启动检查每天最多一次，可以关闭。

主界面“有更新”按钮与悬浮球上的橙色圆点会保留提醒。通过悬浮球菜单也能打开更新页。程序安装包由用户手动下载并启动安装器，词库更新可独立完成。

更新会核对版本、ID 和 SHA256；校验失败不替换已有词库。个人术语，以及已有档案中自行修改、禁用或删除的条目会保留。删除整个档案后不会自动重新添加。保留的个人条目可能与新版公共译名不同，可在术语管理中自行调整。

公开库沿用历史内置档案，并未新增第三方汉化全文。现有英文、日文条目及其中文译名仍需逐步补全出处；待核对条目保持禁用。四语互译不代表内置档案已经具备韩语专名。

## 维护者如何发布词库

1. 按 [术语贡献说明](../CONTRIBUTING.md) 核对反馈。编辑 `limbus-company.ggprofile.json` 中的术语，记录原语言、出处、核对状态及需要纠正的旧译名。
2. 为实际改动增加版本号，如 `2026.10.8.1` → `2026.10.8.2`。不要在相同版本下修改公开文件，客户端不会把同一版本当作新更新。
3. 在仓库根目录运行以下命令。工具默认保留已有 JSON 的修改，更新版本和校验清单。

```powershell
dotnet run --project tools/TermLibrary -c Release -- terminology 2026.10.8.2
dotnet run --project tools/TermLibrary -c Release -- terminology --check
```

4. 将词库与清单放在同一个提交中，推送到 `main`。GitHub Actions 会检查二者是否一致。只有需要改动程序时才另外打包 Release；公共词库更新不要求重新发布程序。
5. 核对 GitHub 原始文件中的版本与哈希，再在反馈 Issue 中回复版本和获取方法。网络缓存可能短暂保留旧版本，可稍后再次检查。

`.gitattributes` 禁止 Git 改写这两个 JSON 的换行，确保下载内容与 SHA256 一致。不要只修改清单而不核对数据。

仅在明确要重新导出代码中的默认档案时使用 `--from-code`；该选项会替换 JSON 中的编辑。恢复旧代码导出不是日常更新步骤。

```powershell
dotnet run --project tools/TermLibrary -c Release -- terminology 2026.10.8.2 --from-code
```

程序重新打包时包含当前 JSON，因此新版安装后的公共基线也随之更新。应用更新时继续保留个人修改；导入第三方或自建档案仍采用独立副本。
