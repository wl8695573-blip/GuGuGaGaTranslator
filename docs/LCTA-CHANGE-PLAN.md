# LCTA 修改计划与验收标准

更新日期：2026-10-08。本文用于安排修改、记录进度，以及让后续维护者找到对应代码。

**首批实现已完成 1.4.0 本机验收，并纳入 LCTA 1.5.0。** 本文保留首批验收基线，后续四语、悬浮球、手动字幕与词库更新进度见 [1.5 修改记录](LCTA-1.5-WORKLOG.md)。 下表记录实际范围；未勾选的真实游戏、在线服务和资料审核项目仍待完成。检查方法、结果与限制见 [验证记录](VERIFICATION.md)。

## 一、产品方向

- 名称：**LCTA**，英文全称为 Limbus Company Translation Assistant，中文介绍使用“边狱巴士翻译助手”。
- 图标：使用维护者选定的橙、白、黑“边·译”字标。窗口小图标与宣传字标共用来源，必要时另做便于小尺寸识别的版本。
- 主要用途：识别《边狱巴士》的剧情文字，在悬浮层显示中文译文，尽量保持角色名和专有名词一致。
- 保留通用框选翻译，供网页、英文文章以及其他固定字幕游戏使用；通用模式不能强制套用边狱巴士术语或日译中设置。
- 首先完善剧情阅读。战斗技能、状态说明、多栏界面和更多游戏术语放在后续阶段。
- 继续维护原仓库与版本历史。仓库改名、应用改名、发布新版分别记录，避免用户把源码改动当成已发布更新。

## 四、逐项修改与验收

### B01：名称与图标

**修改内容**

- 检查主窗口、首次设置、托盘、消息、安装器、卸载、快捷方式及发行文件，统一面向用户的 LCTA 名称。
- 保留旧配置和安装识别信息，避免丢失密钥、选区、服务配置和自定义档案。
- 检查“边·译”在任务栏、托盘和 Windows 应用列表的小尺寸显示；字标过细时另做简化图标，不擅自替换维护者选定的构图。
- 更新 README、使用说明和截图，明确 LCTA 与旧名称的关系。旧版本文件名和历史记录保留原样。

**验收标准**

- [ ] 新版可读取一份旧配置，翻译方向、选区和个人术语不丢失。
- [x] 从 1.3.2 安装版升级后，新入口可用；旧快捷方式得到处理，应用列表没有重复登记。
- [x] 安装目录中的用户额外文件不被升级清理误删。
- [ ] 小尺寸图标可辨认，主程序、安装器与卸载入口名称一致。

**代码入口：** `Directory.Build.props`、`src/Shared/InstallationManifest.cs`、`src/GuGuGaGaTranslator.App/Assets`、`tools/Icon`、`tools/Installer`、`build.ps1`、`tools/publish.ps1`。

### S01：悬浮层稳定性

**修改内容**

- 复查外观预设和翻译选项切换，防止事件递归、重复创建窗口以及后台更新访问已关闭窗口。
- 控制条提供明确的拖动柄与关闭按钮；关闭后停止翻译并释放会话，晚到的结果不能重新弹出悬浮层。
- 区分编辑模式与鼠标穿透模式，让用户知道何时能移动、缩放和滚动译文。
- 长译文限制在工作区内，提供滚动或展开方式；保留易读的字号、背景与原文显示选项。
- 若外观预设仍无法稳定维护，先简化预设数量，再决定是否移除。不能把删除按钮当成完成拖动、关闭问题的修复。

**验收标准**

- [x] 连续切换外观、语言方向和档案各 20 次，无卡死、闪退和重复窗口。
- [x] 控制条和译文框都能按约定移动，关闭、重新开始循环 10 次可正常工作。
- [x] 在翻译请求尚未返回时关闭，返回结果不重新显示窗口。
- [x] 鼠标穿透能恢复；长译文、缩放及屏幕边缘位置可正常操作。

**代码入口：** `src/GuGuGaGaTranslator.App/OverlayWindow.cs`、`LanguageBarWindow.cs`、`AppSession.cs`、`Theme.cs`。

### S02：遮挡与选区

**修改内容**

- 优先使用目标窗口捕获，避免译文框、控制条及其他窗口进入 OCR 输入。
- 保留兼容捕获后端；不能捕获、窗口最小化或画面失效时显示原因和恢复办法，避免不断翻译黑屏或旧画面。
- 窗口移动、客户区尺寸变化、DPI 变化时正确换算选区；选区失效时提示重新框选。
- 默认译文尽量避开原字幕，记住用户调整的位置。抓屏不受遮挡影响与阅读时不遮住字幕都需要检查。

**验收标准**

- [x] 译文框或其他窗口覆盖选区时，支持目标窗口捕获的场景仍识别目标原文。
- [x] 兼容后端的限制能被用户理解，不宣称所有捕获方式都能消除遮挡。
- [ ] 在可用设备上检查 100%、125%、150% 缩放，以及窗口移动、缩放和跨屏操作。
- [ ] 最小化、恢复、切换目标窗口后没有错位、旧帧持续翻译或窗口越界。

**代码入口：** `src/GuGuGaGaTranslator.Core/Capture/WindowCapture.cs`、`ScreenCapture.cs`、`TargetRegionResolver.cs`、`SelfWindowMask.cs`；应用层 `RegionSelectorWindow.cs`、`AppSession.cs`。

### U01、G01：首页与场景设置

**修改内容**

- 首页按“选择窗口 → 确认文字区域 → 开始翻译”组织；服务、OCR 和悬浮层详细选项放入设置。
- 首次使用解释服务地址、模型和密钥的填写方式；测试连接结果区分地址错误、鉴权失败、限流及超时。
- 显示当前窗口、通用／边狱巴士模式、语言方向和识别状态，避免用户不知道为什么用了日译中。
- 现有标题匹配结合进程信息改进识别，允许手动覆盖。离开游戏或选择网页时不能继续误用游戏档案。
- 记住不同目标的选区与用户选择；是否按窗口独立保存更多设置，需先检查现有配置结构再实现。
- 当前支持范围按实际 OCR 和翻译能力填写；韩语等新增语言必须先验证模型，不能只添加菜单选项。

**验收标准**

- [x] 新配置下，英文网页使用通用模式并能明确选择英译中；不会自动强制日译中。
- [x] 边狱巴士档案自动识别失败时，用户可手动选择并看见当前模式。
- [x] 用户主动修改语言方向后不会被后台匹配反复覆盖。
- [ ] 首次配置失败有可操作提示；保存后再次启动不要求重复填写。

**代码入口：** `src/GuGuGaGaTranslator.App/MainWindow.xaml`、`MainWindow.xaml.cs`、`SetupWindow.xaml.cs`、`AppSession.cs`；核心层 `src/GuGuGaGaTranslator.Core/Config/AppConfig.cs`、`Translation/GameProfile.cs`。

### O01：完整台词识别

**修改内容**

- 检查打字机字幕逐字出现时的行为，优先在文字稳定后提交整句；稳定等待时间根据实际样本调整。
- 区分换行、轻微 OCR 抖动、同一句重复出现和真正的新台词；保留取消过期请求的能力。
- 切换场景、菜单或目标窗口时清理过期识别状态，避免持续显示上一句。
- 对识别失败提供查看原文、重新框选或调整 OCR 的入口，避免悄悄把乱码送去翻译。

**验收标准**

- [x] 使用逐字出现的样本时，默认策略不为每个新增字符发送翻译请求。
- [x] 一句稳定显示期间不重复发起同样请求；下一句完整出现后能及时更新。
- [x] 快速换句后显示最新台词，不被较慢返回的旧请求覆盖。
- [ ] 英文报纸、游戏剧情、两行字幕分别保留识别样本和实际结果。

**代码入口：** `src/GuGuGaGaTranslator.Core/Pipeline/TranslationPipeline.cs`、`src/GuGuGaGaTranslator.Core/Ocr`、`src/GuGuGaGaTranslator.Ocr.Rapid`、应用层 `AppSession.cs`。

### T01、T02：术语、上下文和语气

**修改内容**

- 审核内置术语，优先处理标记“待核对”的条目；缺乏依据的候选译名不能默认作为强制纠正规则。
- 档案已有作者、来源、许可和版本字段，先补齐现有字段。若增加逐条出处、核对状态或版本信息，需保证旧档案仍可导入。
- 明确“个人覆盖 → 当前档案 → 通用翻译”的优先顺序；提供恢复内置版本的办法。
- 按原文匹配必要术语，控制提示词大小；避免把整份词库和无关世界观重复发送给模型。
- 利用现有上下文和角色风格提示，避免过度改写。说话者识别不确定时，不强行套用某位角色口吻。
- 换窗口、切档案、明显场景切换时清理上下文；不主动补入用户尚未看到的剧情。
- 检查传统翻译后的术语替换，避免短词、同形词和普通词被无条件替换。

**验收标准**

- [ ] 英文和日文术语分别核对，保留可追溯出处或明确的候选状态。
- [ ] 用户覆盖、禁用和恢复术语后确实生效，导入旧档案不会丢字段或崩溃。
- [x] 普通文章不出现边狱巴士专有译名；同形词有负例检查。
- [x] 提示词预览能解释使用了哪些档案信息；短上下文有上限并能按场景清理。
- [ ] 人物风格以准确、易读为前提，不擅自补充剧情、身份和未出现的信息。

**代码入口：** `src/GuGuGaGaTranslator.Core/Translation` 下的 `LimbusProfile.cs`、`GameProfile.cs`（含术语表）、`TermEnforcer.cs`、`TermSheetBuilder.cs`、`OpenAiCompatibleTranslator.cs`；`Pipeline/TranslationPipeline.cs`；应用层 `GameProfileWindow.xaml.cs`、`PromptPreviewWindow.xaml.cs`。

### F01、P01：请求、缓存与隐私

**修改内容**

- 区分网络不可用、密钥无效、额度或限流、模型错误与 OCR 失败；错误不导致程序退出，也不无限重试。
- 停止、关闭、切服务和切档案时取消旧请求，避免旧结果覆盖新会话。
- 检查缓存键与失效策略是否覆盖模型、服务、语言方向、档案和术语变化；上下文相关结果不能跨场景盲目复用。
- 复查密钥保存、诊断导出和截图调试路径。密钥不进入日志，台词、截图和译文不默认进入诊断包。
- 说明离线 OCR 与联网翻译的区别，以及用户所选服务会接收什么内容。连接测试发送示例文本并可能计入用量，应继续明示。
- 整理图标及术语来源记录；有争议的使用条件在发布前处理，不能把开源、改字或资料公开等同于获得授权。

**验收标准**

- [x] 模拟超时、鉴权失败、限流和取消，界面仍可操作；重试行为有上限。
- [x] 改模型、方向、术语或档案后，不直接返回与新设置不符的旧缓存结果。
- [x] 停止后没有持续请求，关闭窗口后没有后台异常重新弹窗。
- [x] 导出的诊断包没有密钥、真实台词、译文或截图等默认不应包含的信息。
- [ ] 第三方说明有真实来源；未确认的授权、合作及官方认可没有被写成事实。

**代码入口：** `OpenAiCompatibleTranslator.cs`、`TranslationPipeline.cs`、`TranslationCache.cs`、`ConfigStore.cs`、`SecretProtection.cs`、`src/GuGuGaGaTranslator.Storage.Sqlite`、核心层 `Diagnostics`、`THIRD_PARTY_NOTICES.md`。

### C01、E02：术语提交与更新

**修改内容**

- 继续使用 GitHub Issue 表单收集原文、语言、建议译名、出处及理由，由维护者审核后收录。
- 回复中说明接受、待核对或不采用的原因；收录时附对应修改或版本，用户能知道何时获取。
- 本地编辑、自定义档案分享与内置词库更新分别说明。目前没有自动同步，文档不能暗示提交后会立即更新所有用户。
- 后续术语更新应显示来源、版本和变更，允许用户确认导入，保留个人覆盖并支持回退。
- 与零协会沟通前，先整理拟使用的具体资料、获取方式、分发形式及许可记录。图标来源与术语来源分别处理。

**验收标准**

- [x] 用户无需改代码，就能按 [贡献说明](../CONTRIBUTING.md) 提交完整反馈。
- [ ] 反馈能追踪到处理结论和获取方式，涉及剧情的截图有剧透提示。
- [ ] 若实现更新，更新失败不损坏已有档案，更新成功不抹掉个人术语。
- [ ] 外部接入只使用确认过来源及条件的数据，不能宣称已有合作。

**入口：** `.github/ISSUE_TEMPLATE/terminology.yml`、`CONTRIBUTING.md`、[档案说明](PROFILES.md)、`GameProfileArchive.cs`、`LimbusProfile.cs`。

### E01、M01、A01：后续改进

- **E01：** 先核对现有复制、原文查看和历史能力，再补当前句重译、历史检索和可选导出。默认限制保存量，并提供清空操作。
- **M01：** 记录启动时间、OCR 耗时、请求数、翻译耗时、内存和长时间运行情况。标明硬件、模型、网络和样本，取得基线后再制定目标。
- **A01：** 战斗技能、多块选区、韩语 OCR 和更多游戏档案单独立项，先收集样本并验证识别效果。

**验收原则：** 可选功能不干扰开始／停止翻译；指标来自实测；资料导出不默认开启；尚未验证的能力不写进支持列表。

2. **首个 LCTA 剧情版本：** 优先 U01、G01、O01，再处理 T01、T02、F01、C01。每批改动后更新本文，避免一次混入过多未验收功能。
3. **发布后改进：** 按真实反馈安排 E01、M01；外部资料条件明确后再安排 E02。
4. **扩展场景：** A01 单独规划，避免影响已有剧情翻译流程。

1.4.0 是当前开发版本号，不代表上述全部任务已经承诺在这个版本完成。发布前在更新记录中列出实际完成的范围，剩余任务继续保留。
